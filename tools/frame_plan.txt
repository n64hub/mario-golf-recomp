# Mario Golf's frame-dump plan: one run of the desktop build through every screen a player meets, played in a 16:9, a
# 4:3 and a 32:9 window while the build dumps its frames, the three dumps then checked against each other by machine.
# A check fails only what a plan plays, so a scene a player reports a fault in that this doesn't reach is added here by
# the work that fixes it.
# Each line is a step at seconds since the program started: `key <name>` presses and releases a key in the window,
# `shot <name>` captures it, `poke <addr> <value>` writes a 32-bit word of RDRAM, and
# `until <addr> <mask> <value> <timeout s> [key]` waits until the word at addr anded with mask is value, pressing key
# every 1.5 s meanwhile if it isn't yet; the later steps move on by its wait, so the three runs keep step with the game,
# not the clock, and an until unmet by its timeout fails the run. Addresses are the USA ROM's (syms/).
# Overlays: the loaded byte at the head of each 0x28-byte entry of the overlay table at 0x800B5F58 (CLAUDE.md, The
# code; tools/shader_survey.js): 8 the title, 3 the main menu and the menus after it, 4 a hole's flyover, 2 any hole
# (with 11 in most modes, 13 in Ring Shot and Training), 16 the end credits. Keys are the keyboard's defaults: Enter
# Start, Space A, WASD the stick. A press can be lost on a busy host (a late step's keys also come in a burst, which
# the game takes as one), so each step whose miss would leave the plan out of step presses until RAM shows it took: the
# menu screen (0x801EFFA0: 0 the main menu, 1 Character Select, 5 Play Modes, 6 a mode's course or hole select), the
# Play Modes cursor (the low byte of 0x801323A8, the mode from 0 in the order below), Training's hole (0x800F72F0,
# from 1), the pause (1 in the low byte of 0x800C306C while paused) and its menu's cursor (the low byte of
# 0x80224924, the item from 0), whose last item, W from the first, is Save and Quit (by the save menu) or Return to
# Menu; the main menu is waited for with A pressed, which a save menu takes and the main menu's zoom drops.
# Each swing plays the same shot in every window, which presses can't: the swing meter (the word at 0x800FBE88) counts a
# game frame at a time from the first press, and a press reaches the game a frame early or late. So it is played as the
# game plays a computer golfer's (func_ovl0_802088B0): with 0x80227194 set, the meter stops itself on the frame it
# reaches the power and impact in 0x80104F7C and 0x80104F80, with the stick at impact from 0x80104F8C and 0x80104F90 (0,
# none); a putt takes no impact, and goes at the power. A press of A starts the meter, and the flag is set after it,
# since a computer golfer's aim is turned to 0x80104F78 before then. The wind, which the hole draws with rand() as its
# flyover ends, a frame apart in each window, is set half a second after each hole's flyover ends, so its tee shows the
# same wind in every window, and again before each swing, but in Mini-Golf, which has none: its speed (16.16) and
# heading (the high half) at 0x800BA9F0 and 0x800BA9F4, and the vector the game works out of them at 0x80104F44 and
# 0x80104F4C (func_8007E7B8). And rand() (its state at 0x800FBD30), called 6 times a game frame and once more as the
# ball is struck, and so at another point in each window by then, is seeded with the wind on the tee, and a few frames
# before the meter's last stop with the meter set back to the start of the 4 values its wait takes (0x24, or 0x0C for
# the putt): a poke that lands a frame late sets the meter back that frame too, so the seed is always the same number of
# frames from the stop. The shots still land apart, 4 to 17 yards, from run to run and in the same window as much as
# across them (Tournament's first, eight times: 302, 307 or 319 yards left), for a cause not yet found, and on each tee
# the golfer's practice swing and the caddie's walk are at another point in each window (up to 1.3 s unlike), timed by
# neither the wind nor the seed. So each hole with a swing is left out of the middle check (`unchecked middle`) from its
# tee, as its flyover ends, to its pause (to the next hole's flyover in Mini-Golf, from Lakitu's count-in in Speed Golf,
# which the plan's presses of A meet at another point in each window), Get Character's from its opening, its flyover
# 0.9 s unlike, and Training's Yoshi's Island hole from the course's change to its pause, its doors and flyover 1.0 s
# unlike. The putt holes out in every window and run all the same.

# (0x800C401C = 0), then the credits (scene 0x1E) play whole, the names rising beside the course in its box, until
# their timer (0x801F89A4) passes 0xE00, and the Congratulations picture fades in. The golfers the box shows are a
# rotation of all 18 from the one played, which the credits' start (func_ovl16_801F4B9C) shuffles with 160 calls of
# rand() unless debug flag 0x99 is on (func_800299F4, the flags' bits from 0x801052F8, 0x80 the first): the plan sets
# it (0x40 in 0x8010530B, its only reader that shuffle) and seeds rand() (its state at 0x800FBD30, which the credits
# also draw on for their shots) as the fade is let through, so every window shows the same golfers in the same order.
